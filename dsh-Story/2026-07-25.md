## 2. 设计模式与重构

### 应用的设计模式

- **Storage Hub Pattern**：`feat(storage): storage hub with named backend registry and data-form mounts` 引入了存储中心，支持多后端注册和数据表单挂载。这是 **Abstract Factory Pattern** 的应用。
- **Domain Form Pattern**：`feat(storage): domain data form — typed schemas over opaque KV units` 引入了领域表单，将类型化 schema 应用于不透明的 KV 单元。这是 **Value Object Pattern** 的体现。
- **Retry Policy Pattern**：`feat(llm): add per-provider retry policies` 为每个 LLM provider 添加了独立的重试策略。这是 **Strategy Pattern** 的应用。

### 模块解耦与接口定义

- **CLI 统一**：`refactor(cli): unify the arg grammar — one program, --config flag, real web subcommand` 将 CLI 参数解析统一为单一程序、config 标志和 web 子命令。
- **存储后端分离**：`feat(storage): json backend` 和 `feat(storage): sqlite backend` 将存储后端分离为独立的实现。
- **子代理策略继承**：`subagent: inherit parent sandbox/approval overrides in in-process children` 实现了子代理的策略继承。

### 基础设施与性能

- **Mock Fault Server**：`feat(llm): add scriptable mock fault server` 添加了可脚本化的 mock 故障服务器，用于测试。
- **遥测脱敏**：`refactor(telemetry): ship the redact waterfall without built-in rules` 实现了无内置规则的脱敏瀑布。

## 3. 特性交付与系统影响

### 核心特性

- **存储中心**：`feat(storage): storage hub with named backend registry and data-form mounts` 实现了多后端存储中心。
- **LLM 重试策略**：`feat(llm): add per-provider retry policies` 为每个 LLM provider 添加了独立的重试策略。
- **推理努力控制**：`feat(llm): add model-specific reasoning effort controls` 实现了模型特定的推理努力控制。
- **会话遥测**：`feat(telemetry): session-telemetry seam with mandatory redaction + OTel backend` 实现了会话遥测和 OTel 后端。

### 系统拓扑影响

- **存储中心**改变了数据存储的架构，影响了 session、workspace 等存储组件。
- **LLM 重试策略**改变了 LLM 调用的容错机制，影响了 llm、provider 等组件。
- **子代理策略继承**改变了子代理的行为方式，影响了 subagent、sandbox 等组件。

## 4. 架构决策与 Roadmap 对齐

### 关键技术决策（ADR 推断）

- **背景与痛点**：存储层缺乏统一的抽象，LLM 调用缺乏重试机制，子代理缺乏策略继承。
- **选择的方案与 Trade-offs**：
  - Storage Hub：选择引入存储中心而非继续使用分散的存储，提高了统一性但增加了抽象层。
  - Retry Policy：选择为每个 provider 添加独立策略而非统一策略，提高了灵活性但增加了复杂度。
  - Policy Inheritance：选择在 in-process 子代理中继承策略，而非跨进程传递，简化了实现但限制了范围。

### 产品 Roadmap 支撑

- 存储中心支撑了数据持久化和管理。
- LLM 重试策略支撑了调用的可靠性。
- 推理努力控制支撑了模型性能优化。
- 会话遥测支撑了可观测性。
