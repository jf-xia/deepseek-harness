## 2. 设计模式与重构

### 应用的设计模式

- **Explicit Send Options**：`refactor(agent): require explicit send options` 和 `refactor(agent): require complete send options` 强制要求显式传递发送选项，消除了隐式默认值。这是 **Explicit is better than Implicit** 原则的体现。
- **Delivery Methods by Intent**：`refactor(agent): name delivery methods by intent` 将交付方法按意图命名，提高了代码可读性。
- **Inbox Message Minimization**：`refactor(agent): minimize inbox message contract` 最小化了收件箱消息的契约，减少了不必要的字段。

### 模块解耦与接口定义

- **Agent Loop 简化**：`refactor(agent-loop): simplify observable state machine` 和 `refactor(agent-loop): simplify turn driver` 进一步简化了状态机和 turn driver。
- **Eager Persistence 依赖**：`refactor(agent-loop): rely on eager session persistence` 将 Agent Loop 的持久化依赖从懒加载改为急切模式。
- **Session Metadata 契约**：`fix(sqlite): preserve session metadata contracts` 确保了 SQLite 存储的元数据契约一致性。

### 基础设施与性能

- **CI 企业级优化**：`ci: isolate enterprise Linux critical paths` 和 `ci: rebalance paid runner gates` 继续优化企业级 CI。
- **Coverage 优化**：`ci: coverage skip part of web` 和 `ci: coverage skip part of server` 针对性地跳过不需要的覆盖率收集。

## 4. 架构决策与 Roadmap 对齐

### 关键技术决策（ADR 推断）

- **背景与痛点**：Agent Loop 的消息状态机仍然过于复杂，send 接口的隐式默认值导致了多个 bug，会话元数据的契约不一致影响了数据一致性。
- **选择的方案与 Trade-offs**：
  - Explicit Send Options：选择强制要求显式传递选项，增加了调用成本但消除了隐式默认值。
  - Delivery Methods by Intent：选择按意图命名方法，提高了可读性但可能需要更新所有消费者。
  - Eager Persistence 依赖：选择将 Agent Loop 的持久化依赖改为急切模式，提高了数据安全性但可能增加耦合度。

### 产品 Roadmap 支撑

- Plan Mode 控件支撑了任务规划功能。
- 模型选择器支撑了模型切换能力。
- 权限预设支撑了审批流程。
- Todo 显示支撑了任务跟踪功能。
