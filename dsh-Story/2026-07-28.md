## 2. 设计模式与重构

### 应用的设计模式

- **Checkpoint/Restore Pattern**：`feat: dsh-session-projection-cache — durable projection checkpoints and the cold-read ladder` 引入了 checkpoint/restore 模式，projection 状态可以持久化到磁盘并在需要时恢复。
- **Cold-Read Ladder Pattern**：projection cache 实现了 cold-read ladder，从内存 → 磁盘 → 重新计算的层级读取策略，优化了启动和恢复性能。
- **Watermarked Block Pattern**：`fix(apiproxy,client): the list projection column becomes a seedable watermarked block` 将 list projection 列重构为可 seed 的 watermarked block，支持增量更新。
- **Capability Seam Pattern**：`feat(host,client): compose directory picking through slots — dual-face -native, no wire advertisement` 实现了 directory picker 的 capability seam，通过 slot 机制组合 dialog 和 browse 后端。
- **Constructor-seeded Inheritance Pattern**：`docs(policy): describe constructor-seeded inheritance` 定义了 constructor-seeded 继承模式，策略在构造时注入而非运行时查询。

### 模块解耦与接口定义

- **Projection Cache Seam**：将 projection cache 拆分为 checkpoint/restore 接口和 cold-read ladder 实现，遵循了 capability seam 的三角色架构。
- **Directory Picker Seam**：将 directory picker 拆分为 dialog backend 和 browse backend，通过 slot 机制组合，实现了 "dual-face -native" 的双面架构。
- **Client Service Interfaces**：`refactor(client): carve outward interfaces for the session, workspace, layout, slash, and conversation services` 为 client 端的多个服务定义了 outward interface，实现了接口与实现的分离。
- **Goal Type Outlet Split**：`feat(goal): split the pure type outlet and register the 'goal' projection unit` 将 goal 的类型 outlet 分离，使其成为独立的 projection 单元。

### 基础设施与性能

- **Native TypeScript Loading**：`feat: launch dsh source with native TypeScript` 和 `vendor: support native TypeScript source loading` 实现了原生 TypeScript 加载，避免了编译步骤，提升了开发体验。
- **Snapshot Canonicalization**：`test(snapshot): canonicalize generated cwd tokens` 使 snapshot 中的路径令牌标准化，提升了测试的可重复性。
- **Gate Plan Replay**：`test(dev-infra): exercise replay diagnostics` 验证了 gate plan 的重放诊断能力。

## 3. 特性交付与系统影响

### 核心特性

- **Projection Cache**：这是当日最大的架构交付。checkpoint/restore faces、cold-read ladder 和 seedable watermarked block 共同建立了 projection 状态的持久化和恢复机制，使得 session 恢复时不需要重新计算所有 projection。
- **Directory Browser**：capability seam 的 dialog + browse 双面架构使得 workspace 目录浏览成为可能，支持 native flow 和 web flow 两种模式。
- **Goal Domain**：goal 作为新的 projection 单元注册到 session projection 框架，验证了 projection 框架的可扩展性。
- **Native TypeScript Launch**：原生 TypeScript 加载使得 `dsh` 可以直接从源码启动，无需编译，大幅提升了开发迭代速度。

### 系统拓扑影响

- **Projection 持久化路径变化**：projection cache 引入了 `memory → disk → recompute` 的三级读取路径，改变了之前只在内存中计算的模式。
- **Directory Picker 能力**：directory picker 作为新的 capability seam，影响了 workspace 管理和文件操作的能力边界。
- **Native TS 启动路径**：native TypeScript 加载改变了 `dsh` 的启动路径，从 `compiled lib/` 变为 `source src/`。

## 4. 架构决策与 Roadmap 对齐

### 关键技术决策（ADR 推断）

**ADR-004: Projection Cache 的 Checkpoint/Restore 机制**
- **背景与痛点**：session 恢复时需要重新计算所有 projection，导致恢复时间长。
- **选择的方案与 Trade-offs**：引入 checkpoint/restore 机制，将 projection 状态持久化到磁盘。牺牲了磁盘空间，换取了恢复速度。

**ADR-005: Directory Picker 的 Dual-face 架构**
- **背景与痛点**：workspace 目录浏览需要同时支持 native 和 web 两种模式。
- **选择的方案与 Trade-offs**：引入 capability seam 的 dual-face 架构，通过 slot 机制组合 dialog 和 browse 后端。增加了架构复杂度，但获得了模式灵活性。

**ADR-006: Native TypeScript 启动**
- **背景与痛点**：每次代码修改都需要编译才能测试，开发迭代速度慢。
- **选择的方案与 Trade-offs**：引入原生 TypeScript 加载，通过 vendor 的 native TS loading 支持。牺牲了运行时性能（首次加载较慢），换取了开发体验。

### 产品 Roadmap 支撑

- **Projection Cache** 支撑了 session 的快速恢复，是用户切换 session 时性能的关键改进。
- **Directory Browser** 支撑了 workspace 管理的 GUI 化，降低了用户配置 workspace 的门槛。
- **Goal Domain** 支撑了 goal tracking 的 GUI 展示，是 agent 协作能力的关键改进。
- **Native TS Launch** 支撑了开发者体验的提升，降低了贡献门槛。

## 5. 开发者/架构师决策推断

### 开发者意图重建

- **思维模型**：开发者将 projection cache 视为一个 "持久化层"——projection 状态可以在 session 之间持久化，恢复时从磁盘读取，而不是重新计算。这个模型类似于数据库的 WAL（Write-Ahead Log）。
- **优先级选择**：先建立 checkpoint/restore（核心能力），再建立 cold-read ladder（性能优化），最后建立 watermarked block（增量更新）。这是 "正确性先行" 的策略。
- **有意取舍**：选择了 checkpoint 而非 streaming replication，因为 projection 的更新频率较低，checkpoint 足够满足需求。

### 架构师决策推断

- **模块拆分粒度**：projection cache 被拆分为 checkpoint/restore 接口、cold-read ladder 实现、watermarked block 数据结构，每个职责独立。这个粒度确保了每个包可以独立测试和演进。
- **时机判断**：在 session projection 框架建立后才引入 cache，因为 cache 需要与 projection 框架集成。
- **后续影响**：projection cache 的引入使得 session 恢复速度大幅提升，但也增加了磁盘 I/O 和存储需求。

### Code Review 视角

- **首先关注**：`feat: dsh-session-projection-cache — durable projection checkpoints and the cold-read ladder` 和 `feat(host,client): compose directory picking through slots — dual-face -native, no wire advertisement`。这两个是核心架构变更。
- **会提出的问题**：checkpoint 的失效策略是什么？directory picker 的 dual-face 在 web 和 native 之间的行为差异是什么？cold-read ladder 在并发场景下的竞争条件如何处理？
- **做得好的**：projection cache 的 cold-read ladder 设计考虑了性能和正确性的平衡，directory picker 的 dual-face 架构考虑了模式灵活性。
- **可以改进的**：checkpoint 的失效策略需要更明确的文档，directory picker 的 web 和 native 行为差异需要更清晰的测试覆盖。

## 6. 技术债务与风险评估

### 已知风险 / 变通方案

- **Projection Cache 失效策略**：cold-read ladder 的失效策略尚不明确，可能导致 stale data 问题。
- **Directory Picker 的 Dual-face 一致性**：dialog 和 browse 后端的行为差异可能导致不一致的用户体验。
- **Native TS 启动的性能**：首次加载较慢，可能影响用户体验。
- **Checkpoint 的磁盘空间**：checkpoint 会占用磁盘空间，需要明确的清理策略。

### 建议的下一步

1. **Projection Cache 失效策略文档化**：明确 cold-read ladder 在 session disconnect/reconnect 场景下的行为。
2. **Directory Picker 行为一致性测试**：添加 web 和 native 模式的集成测试，确保行为一致。
3. **Native TS 启动性能基准**：建立 native TS 启动的性能基准，确保不会显著影响用户体验。
4. **Checkpoint 清理策略**：实现 checkpoint 的清理策略，避免磁盘空间无限增长。
